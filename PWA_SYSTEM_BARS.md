# Hi-Vet PWA: Android system bars and installed-app panels

Reviewed on October 31, 2026 (Asia/Manila).

## What is supported

Hi-Vet already declares `display: standalone` in all four manifests and `viewport-fit=cover` in `frontend/index.html`. These settings are retained. The existing hero image, image sizing, fonts, colors, menus, content, and page layout are unchanged by this update.

Chrome can expose the bottom gesture-navigation area to web content. `viewport-fit=cover` is the supported opt-in. Safe-area insets protect controls when the browser exposes an area that system UI can cover. This opt-in does not itself guarantee a transparent status bar. Source: [Chrome edge-to-edge guide](https://developer.chrome.com/docs/css-ui/edge-to-edge).

The actual image can appear in an area only when Chrome includes that area in the web viewport. Current Chromium documents non-immersive top-edge drawing for installed web apps behind `WebAppShortEdgesCutoutMode` and a default-off `enable_standalone` parameter. These browser-controlled features cannot be enabled with a website setting. Availability depends on the installed Chrome build and rollout. Source: [Chromium Android architecture](https://github.com/chromium/chromium/blob/main/components/webapps/docs/android_architecture.md#display-modes-and-immersive-mode).

Therefore full image visibility behind both visible system bars cannot be guaranteed by this PWA-only change. No native wrapper, fullscreen request, browser flag change, duplicated background image, negative-margin trick, or transparent-color claim was introduced. Fullscreen would hide the system bars and would violate the requirement to retain the clock and other icons. Three-button navigation can also retain browser/OS contrast protection.

The existing dark theme-color hint remains a fallback for browser-controlled system UI and icon contrast on the dark hero. It is an opaque color hint, not an image or a transparency mechanism. The website cannot independently force Android's system-icon colors. Existing light-route hints remain unchanged. The Apple `black-translucent` tag is iOS-specific; it is not an Android fix.

## Files changed for system-bar review and installed-app panels

- `frontend/src/App.tsx`: correct misleading comments around theme-color. Runtime bar-color and page behavior are unchanged.
- `frontend/src/index.css`: correct the viewport comment and import installed-app panel styles. Existing root dimensions and safe-area-aware navigation are retained.
- `frontend/src/pwa.css`: bottom-align the help/legal and Get the App panels only under `@media (display-mode: standalone)`. Cap height below the reported top inset and provide bottom safe-area padding. Ordinary browser dialogs retain their existing presentation.
- `frontend/src/components/Footer.tsx`: mark its existing information dialog for the standalone styles and label the close control. Footer links and their content are retained.
- `frontend/src/components/PwaInstallModal.tsx`: mark the existing install dialog for the same standalone bottom-sheet styles. QR code and installation features are retained.
- `frontend/public/sw.js`: change the cache version to retire the previous cached shell.
- `frontend/tests/pwaSystemBars.test.mjs`: guard standalone display mode and viewport-fit settings.

Inspected without changing: `frontend/index.html`, `frontend/public/manifest.json`, `manifest-customer.json`, `manifest-business.json`, `manifest-rider.json`, the hero components, and existing fixed navigation controls. Their existing PWA opt-ins and image layout require no extra settings. Both installation entry methods use the same web manifest configuration; a shortcut that opens in an ordinary Chrome tab remains subject to normal browser UI behavior.

## QR-link correction included in this update

`frontend/src/utils/pwaInstallUrl.ts` and `pwaManager.ts` build customer, clinic, and rider install URLs using `https://hivet-crm.vercel.app`, with an optional public HTTPS `VITE_APP_URL`. Localhost or invalid overrides fall back to the deployed address. The install dialog shows the deployed hostname. `.env.example`, `frontend/README.md`, and `frontend/tests/pwaInstallUrl.test.mjs` document and verify this behavior.

## Verification and limits

Seven automated checks passed for portal install URLs, invalid/localhost URL settings, standalone manifests, the viewport opt-in, and the existing review-status guard. The production frontend build passed.

The three QR images generated by the actual localhost dialog were decoded successfully:

- Customer: `https://hivet-crm.vercel.app/?pwa=customer`
- Clinic: `https://hivet-crm.vercel.app/login/business?pwa=business`
- Rider: `https://hivet-crm.vercel.app/login/rider?pwa=rider`

In the desktop browser, `display-mode: standalone` correctly remained false. Both the install dialog and the footer information dialog retained their centered browser layout. The available browser tooling cannot emulate installed display mode, so the standalone bottom-panel layout remains a device check, not a claimed installed-app result.

This environment does not provide a physical Android 15 device. Desktop viewport resizing does not reproduce Android system bars, so it cannot prove image transparency, system-icon contrast, or installation behavior. No such physical-device result is claimed.
